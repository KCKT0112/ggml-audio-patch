# 任务包：下发平台绑定的工作

> 中文 | **[English](task-package.md)**

**任务包**（task package）是本仓库在维护者没有对应硬件时，完成"必须在该硬件上构建并验证"的工作的方法。本文把 Metal 一轮（任务包提交 `73cefd2`，执行并合并为 PR #1）的经验提炼成流程，下一轮——CUDA 移植、更新的 ggml 基线、或任何平台绑定的任务——照此打包即可。

## 适用场景

- 工作必须在维护者本地无法运行的平台上验证（Metal 轮：开发在 Windows、无 macOS runner、无苹果设备）。
- 存在可信的上游供体树，代码只需要**集成、不需要重设计**。
- 执行者可以是在目标平台上的真人，也可以是 AI 编程 agent——任务包必须做到不接触维护者也能执行。

## 任务包的构成

### 1. 冻结参考提取 —— `<topic>-reference/`

把供体代码**逐字**提取到独立目录。每个文件头写明来源声明：

- 源 URL、分支、许可证（提取溯源不可删）；
- **状态：仅供参考**——本仓库的平台不编译、不验证，避免被误当成已测试产物；
- 编辑规则：kernel 体与 struct 字段顺序不可改；编译不过时改*集成胶水*，绝不改提取内容。

为什么：执行者不必猜测上游意图，不能"好心"重写可信的数学逻辑，溯源集中一处可审计。

### 2. 移植与验证指南 —— `docs/<topic>-porting.md`（+ `_zh`）

任务说明书本体。Metal 轮行之有效的做法：

- **先讲可行性**：一张逐项对照表，说明供体的 API 约定与目标基线一一对应（encoder API、kargs typedef、pipeline 查找、分发 switch、supports_op 形态）。
- **推荐顺序，从最简单的开始**：每一步独立可验证（Metal 顺序：bias_gelu → pw2_residual → edge_pad → snake → layer_norm_channel → depthwise_1d）。
- **逐算子映射**：参考提取的哪一段进哪个目标文件，命名风格照抄。
- **预接测试挂具**：测试钩子在*前一个*补丁里就位、门控未开时干净 SKIP——执行者第一天就从绿色可验证基线开始。
- **验证流程**：目标后端的运行夹在两个绿色 CPU 基线之间。
- **编号且强制的验收标准**：正确性矩阵；无 CPU 回归；不支持形状的干净回落；门控纪律（不许超集）；kernel diff 纪律（`git diff <topic>-reference/` 为空）；确定性（跑两遍比对）；PR 里的平台声明（OS、芯片、工具链、输出结尾原文）；基准鼓励但不阻塞。
- **已知坑**与**不要做的事**——否则会随人员更替丢失的移植知识。

### 3. 编辑边界 —— `AGENTS.md`

在边界表里把参考提取列为冻结产物类别，并在"明确允许"里授权集成以**独立补丁文件 / PR** 形式提交——绝不许静默改动已有补丁。这能让远程执行的 PR 保持小而可审。

## 交接流程

1. 任务包作为单个提交就位：参考提取 + 指南 + 边界 + 前置补丁里预接的挂具（补丁相应重新生成）。
2. 邀请有平台的贡献者。Metal 轮由一位 macOS 贡献者在 Apple M4 硬件上执行（PR #1）。
3. 执行者按指南逐算子推进，开 PR 并附验收标准要求的证据。
4. 评审 = 拿 PR 逐条对照编号验收标准，不做更发散的评判。
5. 合并，然后**清理**（见下）。

## 合并后清理

任务包是脚手架，不是长期产物。合并之后：

1. 删除 `<topic>-reference/` 目录——集成后的代码已在生成的补丁里，溯源保留在文档与合并 PR 中；
2. 把 `docs/<topic>-porting.md` 精简为集成笔记——当前状态、挂具跑法、已知坑、已验证交付——删掉任务说明书章节（前置条件、集成步骤、验证流程、验收标准、不要做的事）；
3. 撤销 `AGENTS.md` 里任务专用的边界规则；
4. 更新 README 引用；值得留下的经验记入本文。

Metal 轮的任务包在历史里仍可读：`git show 73cefd2`（任务包）与 PR #1（执行与证据）。

## Metal 轮的经验

- 冻结 kernel 阻止了好心重写；任何偏离都必须在 PR 里说明理由。
- 预接的 SKIP-all 挂具让"不支持 Metal"本身就是被测试的绿色状态——回落路径在任何 kernel 跑起来之前就可验证。
- 编号验收标准让远程执行的 PR 可以逐行评审。
- 确定性要求抓到了真 bug：多 simdgroup LayerNorm 竞态，只在压力下复现（无 barrier 时 C=256/L=4096 十个进程九个错，加 barrier 后 20/20 通过）。
- 按位置绑定的 kargs 纪律（字段顺序是 host↔shader 间的 ABI）值得单独立规矩。
- 本仓库没有 CI：PR 里的平台声明是唯一的验证记录——必须坚持。
